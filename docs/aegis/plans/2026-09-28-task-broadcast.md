# OVH 任务启动与每日定时播报

## 目标

实现两条互相独立的通知路径：

1. 每次服务启动后，自动分别播报当前正在运行的抢购任务、独服监控任务和 VPS 监控任务一次。
- 系统设置的定时播报区提供总开关和每日 `HH:mm` 时间，并提供四个独立内容开关：`抢购任务`、`独服监控`、`VPS 监控`、`抢购战报`。四个内容开关只影响每日定时播报；启动时的一次性三类任务播报不受它们影响。

通知样式已由用户确认：三类任务分别发送为三条独立消息；标题后保留一个空行；详细字段之间不再空行；`月费`、`安装费`、`总价` 各自独立一行并紧跟在 `数据中心` 后；`自动付款` 是每条消息最后一行。`型号` 与 `Plan Code` 分开显示。

## 用户可见格式

抢购任务：

```text
🛒 正在执行抢购任务

OVH 账号：...
型号：...
Plan Code：...
内存：...
数据盘：...
带宽：...
数据中心：...
月费：...
安装费：...
总价：...
<每个数据中心的抢购数量>
自动付款：...
```

独服监控任务：在价格三行之后追加 `有货提醒`、`无货提醒`、`有货自动下单`，最后为 `自动付款`。

VPS 监控任务：在价格三行之后追加 `有货提醒`、`无货提醒`、`Linux 系统`、`Windows 系统`、`有货自动下单`、`数量`，最后为 `自动付款`。

每个存在的任务实例单独发送；没有对应类别任务时不发送该类别消息。每日定时播报末尾追加一条标题为 `抢购战报` 的订单统计消息，按 OVH 账号分别列出五项：

## 现有 owner 与文件边界

- `backend/internal/types/types.go`：已有 `Config`、`QueueItem`、独服 `Subscription`、`VPSSubscription`、订单历史类型；新增定时播报配置字段并保持旧 JSON/SQLite 配置兼容。
- `backend/internal/config/config.go`：配置默认值与加密持久化 owner；新增默认每日时间（`09:00`）及启用状态兼容处理，默认定时播报关闭，避免升级后突然增加通知。
- `backend/internal/handlers/settings.go`：设置 API 的安全回显和合并保存 owner；新增播报字段校验/返回，不能回显其他敏感凭据。
- `backend/internal/monitor`：现有通知渠道适配、独服订阅快照、价格拆分与格式化 owner；新增任务播报格式化/发送服务，统一复用 Telegram、飞书、QQ 的既有发送入口，不改变事件通知和 outbox owner。
- `backend/internal/app/app.go`：已有队列、账户、VPS 快照和订单历史的线程安全访问 owner；新增只读快照或复用既有 snapshot 方法，不绕过 mutation/persistence 锁。
- `backend/internal/vps/catalog.go`：已有 VPS 型号目录和缓存 owner；为播报补齐 VPS 型号名称、规格、价格所需的只读目录字段，避免另建目录来源。
- `backend/main.go`：启动流程 owner；在所有持久化快照加载且自动监控启动后登记一次性启动播报和每日调度后台任务，使用 `State.GoBackground`，优雅退出时可取消。
- `src/hooks/ovh/use-settings.ts`、`src/pages/SettingsPage.tsx`：新增设置字段和“定时播报”设置区，提供启用开关和每日时间选择。
- `docs/handover/03-API-CONTRACT.md`、`agent.md`：记录设置 API 字段和启动/定时播报边界。

## 数据与格式决策

- 账户名称从 `state.FindAccount(accountID)` 读取；找不到时显示账户 ID，不阻塞整条播报。
- 独服型号从 `state.ServerPlans` 的 `Name` 读取，Plan Code 单独显示；内存、数据盘、带宽使用目录基础规格与任务/订阅参与的选项合并去重后用 ` / ` 连接。
- 抢购任务按账户、型号、Plan Code、选项、自动付款状态聚合，数据中心逐项合并并显示每个数据中心的任务数量；暂停、完成、已下架任务不计入“正在执行”。
- 独服监控使用订阅的账户（自动下单账户；没有时使用默认账户）、过滤条件和通知/自动下单开关；VPS 使用 `AutoOrderAccountID` 或默认账户，并显示 `MonitorLinux`、`MonitorWindows`、`AutoOrder`、`Quantity`。
- 价格统一复用现有 `price.DisplayPrice` 含税拆分口径。每条价格行显示金额和币种；如果多个数据中心价格不同，行内按 `GRA: ...；RBX: ...` 展示；获取失败显示 `暂不可用`，不得阻塞播报或伪造价格。
- VPS 目录当前只暴露部分字段；扩展目录解析以获得可用的名称、内存、数据盘、带宽和月费/安装费/总价信息。无法从公开目录确认的字段显示 `暂不可用`，不猜测。
- 订单统计只加入每日定时播报，不加入启动播报。以最近 24 小时成功下单历史为基础，按订单当前状态区分未支付/已支付；订单金额使用现有订单/历史中可确认的含税金额，缺失时显示 `暂不可用`，不把未知金额当作零。统计查询只读，不改变订单状态。
- 渠道使用已配置的 Telegram、飞书和 QQ；Telegram/QQ 使用同一正文，飞书使用对应标题的普通文本卡片。启动播报和定时播报不增加一键下单按钮。

## 调度与生命周期

- `taskBroadcastEnabled` 默认 `false`；`taskBroadcastTime` 默认 `09:00`，格式严格为 `HH:mm`。
- 每日调度使用北京时间，计算下一个严格晚于当前时间的触发点，避免同一天重复发送；配置变更后后台循环最多在一个短轮询周期内读取新时间，不需要重启。
- 启动播报只调用一次，不依赖定时开关；启动阶段网络发送放到后台 context，不能阻塞 HTTP 服务监听。
- 无任务时不发送对应任务类别；三类均为空时不发送任务消息。定时播报仍可发送订单统计，但若没有可统计订单则发送零值统计，确保定时任务有可观察结果。
- 发送入口复用现有渠道配置检查和全局通知互斥；单个渠道失败不影响其他渠道和后台调度，日志记录失败原因。

## TDD Route

- Route：`auto -> strict`。
- Authority：本次用户已确认的通知格式和新增行为，且涉及配置持久化、调度、订单统计和多渠道发送。
- Test posture：先覆盖纯格式化、配置校验、每日时间计算、任务聚合和订单统计，再覆盖发送入口的测试替身；实现后运行完整 Go/TypeScript/生产构建回归。

## 实施任务

1. 扩展配置类型、默认值、设置 API 和前端 hook/设置区，加入启用开关与每日时间输入及校验。
2. 在监控/通知 owner 中实现三类任务快照转换、字段格式化、价格读取和三条独立消息发送；补齐账户、型号/Plan Code、规格、价格和自动付款字段。
3. 实现订单最近 24 小时统计，并将统计消息限制在每日定时播报。
4. 在 `main.go` 启动完成后登记一次性启动播报和可取消的每日调度循环；确保不重复启动、优雅退出和配置切换安全。
5. 增加单元测试/测试替身，更新 API 合同和 agent 指引。
6. 运行 `gofmt`、定向 Go 测试、`go test ./... -count=1`、`go vet ./...`、`npx tsc -b`、`npm run build`、`git diff --check`，检查通知敏感配置未进入消息。

## 兼容与非目标

- 不改变现有库存上下架通知、抢购成功通知、订单状态通知和通知 outbox 的语义或 owner。
- 不改变现有手动通知发送、QQ/飞书/Telegram 配置和任务的持久化结构语义；新增配置字段可被旧配置安全读取。
- 不在启动/定时播报中执行下单、付款、库存查询副作用或修改任何任务状态。
- 不自动发送真实外部通知进行验证；使用测试替身验证正文和发送路由，部署后再由用户使用真实通道确认。

## 风险与收口

- 任务很多时会产生多条消息；方案 B 是用户明确选择的格式，后续可增加数量上限或汇总策略，但本次不改变。
- 价格和 VPS 规格依赖公开目录/缓存，外部数据缺失时显示 `暂不可用`。
- 每日调度以北京时间为准；计划完成前确认设置 API、调度循环和手动/启动路径互不串扰。
